# design.md — rmurai.com リデザイン仕様

## 1. コンセプト

**「静かな知性 × ターミナルの精度」**

学術的な信頼感（研究者としての実績・落ち着き）を軸にしながら、随所にエンジニア／研究者らしい精密さ（等幅フォント・点滅カーソルなどのターミナル的ディテール）を効かせたダークサイト。

HCAI Institute (hcaii.com) の「大きなタイポグラフィ」「スクロール連動アニメーション」「余白の効いた静けさ」を参照しつつ、配色とモチーフを変えることで独自色を出す。

**参照**: https://hcaii.com/ （タイポグラフィ・アニメーションの質感）
**ベース**: rmurai.com の現行コンテンツ構成（Astro製）

---

## 2. デザイン原則

1. **静けさの中の動き** — 派手な演出ではなく、意味のある場所にだけ動きを与える
2. **精度の演出** — 等幅フォント・プロンプト記号で「研究者兼エンジニア」らしさを表現
3. **可読性優先** — hcaiiより見やすく。コントラスト・行間・余白を丁寧に設計
4. **一貫した間** — アニメーションのタイミング・イージングを統一し、安っぽく見せない

## 3. カラーパレット

| 用途 | カラー | HEX |
|---|---|---|
| 背景（ベース） | ほぼ黒（わずかに温度感あり） | `#0A0A0A` |
| 背景（セクション区切り用、任意） | わずかに明るい黒 | `#111113` |
| 本文テキスト | オフホワイト | `#EDEDED` |
| 補助テキスト（日付・キャプション等） | ミュートグレー | `#8A8A8E` |
| 罫線・区切り線 | ごく薄いグレー | `#232326` |
| アクセント（差し色） | エレクトリックブルー | `#2F6FFF` |
| アクセント Hover/Glow | 明るめブルー | `#5C8CFF` |

- 差し色は**リンク・プロンプト記号・等幅テキスト・ホバー状態**にのみ使用し、多用しない
- 本文と背景のコントラスト比は AA 以上を確保（`#EDEDED` on `#0A0A0A` で問題なくクリア）

## 4. タイポグラフィ

| 役割 | フォント（英語） | フォント（日本語） | Weight |
|---|---|---|---|
| 見出し（Hero名前・セクションタイトル） | Fraunces | Shippori Mincho | 400–600 |
| 本文 | Inter | Noto Sans JP | 300–400 |
| アクセント（日付・タグ・DOI・カーソル） | JetBrains Mono | JetBrains Mono（数字/記号のみ） | 400 |

**タイプスケール（目安）**
- Hero名前: `clamp(2.5rem, 8vw, 5.5rem)`
- セクション見出し: `clamp(1.5rem, 4vw, 2.5rem)`
- 本文: `1rem〜1.125rem` / line-height `1.7`
- キャプション・メタ情報: `0.8125rem`（等幅）

見出しはセリフでゆったりと、本文はサンセリフで読みやすく。数字・日付・DOI・タグ類は等幅フォント＋差し色で「データらしさ」を出す。

## 5. ターミナルモチーフの使い方

独自性を出す核となる要素。使いすぎないことが重要（あくまでアクセント）。

- **プロンプト記号**: 各セクション見出しの前に `>` または `$` を差し色・等幅で表示
  例: `$ publications`
- **点滅カーソル**: Hero の肩書きテキスト末尾に `_` を点滅アニメーションで配置
- **タイプライター演出**: Hero の名前 or 肩書きを1文字ずつ表示（後述アニメーション参照）
- **メタ情報**: 論文の年・学会名、記事の日付を等幅フォント＋差し色バッジ風に表示
- **ホバー時のディテール**: リンクhoverで `[ ]` のような装飾が両端に現れる、等（任意・やりすぎ注意）

## 6. アニメーション仕様

全体のイージングは `cubic-bezier(0.16, 1, 0.3, 1)`（easeOutExpo系）に統一。`prefers-reduced-motion` 環境では全アニメーションを即時表示にフォールバック。

| 箇所 | 演出 | Duration/Delay目安 |
|---|---|---|
| Hero 名前 | 1文字ずつタイプ表示 | 全体 800–1200ms |
| Hero 肩書き | タイプ完了後にフェードイン、末尾カーソル点滅継続 | 400ms、遅延200ms |
| セクション全体 | スクロールで下から8〜16pxフェードイン | 500–600ms |
| リスト項目（論文・記事） | 上から順にスタッガー出現 | 各400ms、項目間delay 60–80ms |
| リンクhover | 下線が左→右に描画 or 差し色グロー | 200–250ms |
| スクロール進捗（任意） | セクション遷移時に薄い罫線がアクセント色で伸びる | — |

**背景演出**: プレーンな黒のまま。ノイズ・粒子・マウス追従などは入れず、動きは文字・要素のアニメーションに集中させる。

## 7. レイアウト構成

現行構成を踏襲した**1ページ長尺スクロール**。

```
[Hero]
  名前（タイプ演出）+ 肩書き + 一言自己紹介
  SNS/外部リンク（GitHub / LinkedIn / ORCID）

[Publications]
  $ publications
  論文リスト（タイトル / 著者 / 学会・誌名 / 年 / DOI）
  ※日付・年・DOIは等幅+差し色

[Blog]
  $ blog
  Zennリンク + 最新記事リスト（タイトル・日付）

[Footer]
  © + SNS/外部リンクの再掲
```

- ナビゲーションは最小限（固定ヘッダーなし、または右上に控えめなセクションインジケータのみ）
- 余白はhcaii同様たっぷりと（セクション間 `120–200px` 目安）
- モバイルではタイプ演出・スタッガーのdurationを短縮し、余白も比例して縮小

## 8. 技術スタック

> この節は当初仕様のまま。実装がここから外れた点は §10 に記録している。

- **フレームワーク**: Astro（静的生成、現行踏襲）
- **スタイリング**: Tailwind CSS（ユーティリティクラスでレイアウト・色・タイプスケールを管理）
- **アニメーション**: [Motion](https://motion.dev)（旧Framer Motion）をReactコンポーネントとしてAstroに部分導入
  - 対象: Hero のタイプライター演出、セクションのスクロールフェード（`whileInView`）、Publications/Blogリストのスタッガー表示（`staggerChildren`）
  - 対象外（Motion不要）: リンクhoverの下線・グローなど単純なCSSトランジションで済む箇所 → Tailwindの`transition`ユーティリティで実装
- **ハイドレーション戦略**: 基本は `client:visible`（画面内に入ってから読み込み、パフォーマンス維持）。Hero部分のみ即時演出が必要なら `client:load` を検討
- **原則**: ページ全体をReact化しない。アニメーションが必要な島（Hero / リスト部分）だけをコンポーネント化し、それ以外は静的なAstro/Tailwindのまま保つ

## 9. アクセシビリティ・その他実装メモ

- `prefers-reduced-motion: reduce` は Motion の `useReducedMotion()` フックで検知し、タイプ演出・スタッガーを無効化してフェードのみ or 即時表示にフォールバック
- 等幅フォントの日本語混在に注意（日本語部分は等幅を無理に当てない）
- フォーカス状態（キーボード操作）も差し色でわかりやすく表示する

## 10. 実装メモ（実装時の判断記録）

仕様からの意図的な差分と、その理由。

### 10.1 Motion は React ではなくバニラAPIで導入し、Reactそのものを削除した

仕様の §8 は Motion を React コンポーネント（`client:visible`）としてAstroに島形式で入れる想定だったが、
実装では **`motion/mini` の `animate` + `inView`** をバニラJSで使い、Reactを一切使わない。

- React + react-dom + Motion for React ≒ 90 kB gzip に対し、現状のクライアントJSは **3.8 kB gzip**（全ページ合計）
- ハイドレーション待ちがないので、Heroのタイプ演出が「Reactが読み込まれる前」に始まる
- 演出対象が opacity / transform だけなので、WAAPI専用の `motion/mini` で十分

そのため §8 の「ハイドレーション戦略（`client:visible` / `client:load`）」と §9 の `useReducedMotion()` は
未使用。reduced-motion は `<head>` のインラインスクリプト（CSSメディアクエリ）で検知している。

**当初は `@astrojs/react` と shadcn/ui を「将来の島のため」に残していたが、後に削除した。**
島が1つも無い状態では `@astrojs/react` が参照されない `client.*.js`（191 kB）をdistに残すだけで、
`components.json` と `src/components/ui/button.tsx` も誰も使わない死んだ足場だった。
依存は16個から6個になり、CSSは 7.8 kB → 5.4 kB gzip に減った。
削除の前後で全ページのスクリーンショットと computed style を突き合わせ、**描画差分ゼロ**を確認している。

UIフレームワークが必要になった時点で `astro add react` と `shadcn init` をやり直せばよく、
使う当てのない足場を抱え続ける理由は無い。

### 10.2 日本語フォントはシステムフォント

`Shippori Mincho` / `Noto Sans JP` を webfont として配信すると、100を超える unicode-range 分割ファイル（合計数MB）
になる。サイトの本文は英語なので、日本語はシステムの明朝／ゴシック（Hiragino, Yu Mincho, Yu Gothic ...）に
フォールバックさせ、明朝＝見出し／ゴシック＝本文というペアリングだけを維持する。
自前配信するのは Fraunces / Inter / JetBrains Mono の3ファミリ（可変フォント woff2、latinサブセット、計106 kB）。

### 10.3 非表示の初期状態は JS が有効なときだけ

`[data-reveal]` の `opacity: 0` は `html.js-motion` の下でのみ適用する。このクラスは `<head>` のインラインスクリプトが
`prefers-reduced-motion` を見てから付与し、同時に2.5秒のウォッチドッグを仕掛ける。`motion.ts` が読み込まれなかった
場合はクラスを外すので、**JSが落ちてもコンテンツが不可視のまま残ることはない**。

### 10.4 カードではなくリスト

Publications / Blog は角丸カードではなく、ヘアラインで区切った1行1件のリストにした。
`$ publications` のプロンプト、右端のカウンタ、左カラムの等幅の年／日付と合わせて、
論文リストらしい「静かな精度」を出すため。ホバー時は上端の罫線がアクセント色で左→右に伸びる。

### 10.5 セクションインジケータ

仕様の「任意」項目。`lg` 以上で画面右端中央に等幅の小さなセクション名を出し、
IntersectionObserver で `aria-current` を切り替える。`prefers-reduced-motion` でも動作する。
